# บทที่ 6 — ตั้ง Scope ให้ดี ก่อนกดเริ่ม Crawl

**เวลาเป้าหมาย:** 4 นาที

## บทพูด

[ภาพบนจอ: Project → Profile → Scope Preview → Crawl]

ใน Toad คำว่า Project คือพื้นที่เก็บงานของเว็บไซต์หนึ่งชุด Profile คือการตั้งค่าที่นำกลับมาใช้ซ้ำได้ ส่วน Crawl คือการรันจริงหนึ่งครั้งโดยบันทึก Snapshot ของค่าต่าง ๆ ไว้

เริ่มจาก Seed URL ที่เป็น Host หลักของเว็บ ตรวจให้ชัดว่าจะรวม Subdomain หรือไม่ แล้วพิจารณาตัดเส้นทางอย่าง Account, Cart, Checkout, Internal Search หรือหน้าที่มี Filter จำนวนมาก เพราะพื้นที่เหล่านี้อาจสร้าง URL ไม่รู้จบหรือมีข้อมูลที่ไม่ควรถูกแตะ

URL Ceiling คือเพดานความปลอดภัย ไม่ใช่จำนวนที่เครื่องมือสัญญาว่าจะ Crawl ให้ถึง ถ้าเราตั้งหนึ่งแสน แต่เว็บมีเพียง 300 URL ผลก็ต้องจบแถว 300 ถ้าสถานะเป็น `limit_reached` แปลว่าเพดานตัดงานก่อนจบ ห้ามเขียนรายงานว่า Crawl ครบทั้งเว็บไซต์

[ภาพบนจอ: Scope Preview แสดง URL ที่ผ่านและถูกตัด พร้อมเหตุผล]

กด Preview ก่อนเริ่มเพื่อดูการ Normalize URL, Host ที่อนุญาต และเหตุผลของรายการที่ถูกตัด เริ่มด้วย Raw HTML เพราะเร็วและบอกได้ตรง ๆ ว่า Server ส่งอะไรมา หากเว็บพึ่ง JavaScript จึงค่อยเลือกตัวอย่างไปทดสอบ Render เพิ่ม

ระหว่างทำงานให้ดูสถานะ `running`, `paused`, `completed`, `cancelled`, `failed` และ `limit_reached` ให้เข้าใจ Pause เก็บ Frontier ไว้เพื่อทำต่อได้ ส่วน Completed ต้องหมายถึงระบบพิสูจน์แล้วว่าไม่มีงานใน Scope ค้างอยู่

[ภาพบนจอ: บันทึก Seed, Scope, Exclusion, Limit, Mode และ Terminal State]

รายงานที่น่าเชื่อถือต้องบอกค่าพวกนี้เสมอ เพราะผล Crawl สองครั้งเทียบกันไม่ได้ หากตั้ง Scope คนละแบบครับ
