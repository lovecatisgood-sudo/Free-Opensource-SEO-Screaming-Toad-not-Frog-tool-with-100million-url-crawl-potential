# บทเรียนโบนัส — Audit เว็บไซต์ DJAI Academy จากงานจริง

**เวลาเป้าหมาย:** 6 นาที ไม่นับรวมในหลักสูตรหลัก 60 นาที

## บทพูด

[ภาพบนจอ: ใช้ `01-live-crawl-completed.png` จากโฟลเดอร์โบนัสภาษาอังกฤษ]

บทเรียนนี้เราจะไม่ใช้ข้อมูลจำลอง แต่จะดูผล Crawl จริงของเว็บไซต์ DJAI Academy ซึ่งเจ้าของหลักสูตรมีสิทธิ์ตรวจ

เราใช้ `www.djai.academy` เป็น Host หลัก ตั้ง Raw HTML Mode ไม่รวม Subdomain และกำหนด URL Ceiling ไว้หนึ่งแสน

ตรงนี้ต้องพูดให้ชัด ตั้งไว้หนึ่งแสนไม่ได้แปลว่า Crawl ได้หนึ่งแสน เว็บไซต์มีรายการใน Scope จริง 287 URL ระบบ Fetch ครบ 287 วิเคราะห์ HTML ได้ 222 หน้า ไม่พบ Fetch Failure และจบงานในเวลาประมาณ 31 วินาที

[ภาพบนจอ: `02-live-audit-summary.png` ซูม 8 Errors, 66 Warnings, 20 Information]

Dashboard แสดง Finding ทั้งหมด 94 รายการ แบ่งเป็น Error 8, Warning 66 และ Information 20 ถ้าเรารีบสรุปว่าเว็บมี Error ร้ายแรงแปดจุด เราจะตกหลุมพรางทันที

เราต้องเปิด Evidence ก่อน

[ภาพบนจอ: `03-noindex-review.png` แล้วต่อด้วย `04-indexability-rule-explanation.png`]

รายการสีแดงทั้งแปดคือหน้า Filter หมวดหมู่ Blog ที่ตอบ 200 แต่ใส่ `noindex` เมื่อตรวจต่อ เราพบว่าทุกหน้าตั้ง `noindex, follow` ชี้ Canonical กลับไปยัง Blog Hub ภาษาไทยหรืออังกฤษ และไม่ได้อยู่ใน Sitemap

รูปแบบนี้มีโอกาสสูงว่าเป็นการควบคุม Duplicate โดยตั้งใจ ถ้าหน้าเหล่านี้มีไว้ให้ผู้ใช้กด Filter เท่านั้น การตั้งค่าปัจจุบันอาจถูกต้อง การถอด noindex เพียงเพื่อให้เลขสีแดงหาย อาจสร้างหน้าซ้ำเข้า Index แทน

แต่ถ้าธุรกิจต้องการให้หน้า Category แข่งขันใน Search สิ่งที่ต้องทำไม่ใช่แค่ถอด Tag ต้องสร้าง URL ที่นิ่ง เขียน Title, Description และเนื้อหาประจำหมวดให้มีคุณค่า ใช้ Self-canonical เชื่อม Internal Link และค่อยใส่ Sitemap หลังตรวจ Production

ดังนั้นผลระดับสูงของ Audit ครั้งนี้คือ ยังไม่พบ Technical Failure ที่ยืนยันว่าเร่งด่วน ทุก Resource ใน Scope ตอบ 2xx, ไม่มี Fetch Failure, Sitemap อ่านได้ และทุกหน้า HTML ที่วิเคราะห์มี Title, Description กับ Canonical

[ภาพบนจอ: `05-near-duplicate-review.png`]

หัวข้อที่ควรตรวจระดับกลางคือ Near-duplicate 24 รายการ กระจุกอยู่ในกลุ่ม QR, Image, PDF และ Media Tools ความคล้ายไม่ใช่ความผิดทันที เพราะเครื่องมือในตระกูลเดียวกันย่อมใช้ Layout ร่วมกัน

เราต้องเปิดคู่ตัวอย่างแล้วถามว่า แต่ละหน้ามี Intent แยกจริงไหม มีคำอธิบาย วิธีใช้ ตัวอย่าง ข้อจำกัด และคุณค่าเฉพาะมากพอหรือไม่ ถ้าเปลี่ยนเพียงชื่อเครื่องมือแต่เนื้อหาแทบเหมือนกัน Search หรือ AI อาจมองไม่เห็นเหตุผลที่ควรดึงแต่ละหน้าแยกกัน หาก Intent ซ้ำจริงค่อยรวมหน้า แต่ถ้างานต่างกันให้เพิ่มความแตกต่างที่มีสาระ

[ภาพบนจอ: `06-live-page-inventory.png`]

งานระดับต่ำคือ Title ยาวกว่าเกณฑ์ 12 หน้า สั้นกว่าเกณฑ์ 3 หน้า Description ยาว 7 หน้า และสั้น 13 หน้า ตัวเลขความยาวเป็นคำแนะนำ ไม่ใช่ Ranking Rule เราควรแก้เฉพาะหน้าสำคัญที่ข้อความไม่ชัด ไม่ใช่ตัดคำเพื่อเอาใจเครื่องมือ

อีกเจ็ดรายการแจ้งว่า Title เท่ากับ H1 ซึ่งไม่ได้ผิดในตัวเอง จึงเป็นข้อมูลให้ตรวจ ไม่ใช่งานที่ต้องแก้ทันที

[ภาพบนจอ: `07-live-crawl-history.png`]

บทสรุปที่เป็นมืออาชีพคือ DJAI Academy มีพื้นฐาน Raw Technical SEO ที่แข็งแรง มีงานตรวจความแตกต่างของหน้ากลุ่มเครื่องมือ มีนโยบาย Filter Page ที่ควรบันทึกให้ชัด และมี Metadata บางหน้าที่ปรับปรุงได้

Audit นี้ยังไม่ได้ตรวจ JavaScript Rendering, Performance, Accessibility, Search Console, Backlink หรือ Rich Result แบบเต็ม จึงไม่ใช้รับประกันอันดับหรือ AI Citation

นี่คือคุณค่าของ Toad ในงานจริงครับ มันไม่ได้มีไว้สร้างตัวเลขน่ากลัว แต่ช่วยพาเราไปถึงหลักฐาน เพื่อให้มนุษย์ตัดสินใจอย่างมีเหตุผล
