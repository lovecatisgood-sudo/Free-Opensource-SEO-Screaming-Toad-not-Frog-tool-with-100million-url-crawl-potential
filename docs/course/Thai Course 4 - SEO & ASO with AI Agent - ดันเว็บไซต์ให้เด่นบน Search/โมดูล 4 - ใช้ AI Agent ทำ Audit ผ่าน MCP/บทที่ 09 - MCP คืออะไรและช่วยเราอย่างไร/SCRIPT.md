# บทที่ 9 — MCP คืออะไร และช่วยลดความยุ่งยากอย่างไร

**เวลาเป้าหมาย:** 4 นาที

## บทพูด

[ภาพบนจอ: AI Client ↔ MCP Server ↔ SEO Screaming Toad]

ถ้าเราใช้ Toad ผ่านหน้าจอเอง เราต้องสร้าง Project ตั้ง Profile กำหนด Scope เริ่ม Crawl รอจนจบ เปิด Issue ทีละรายการ และ Export Report ขั้นตอนไม่ได้ผิด แต่สำหรับผู้เริ่มต้นอาจดูเทคนิคมาก

MCP หรือ Model Context Protocol เป็นมาตรฐานเปิดที่ช่วยให้ AI Application เชื่อมกับข้อมูลและเครื่องมือภายนอกได้ เอกสารทางการเปรียบ MCP เหมือนช่อง USB-C ของโลก AI คือมีรูปแบบการเชื่อมต่อร่วมกัน แทนที่ทุกโปรแกรมต้องสร้างวิธีคุยกับ AI ใหม่ทั้งหมด

เมื่อ Toad มี MCP Server, Codex หรือ Claude Code จะเห็นเครื่องมือที่มีชื่อและหน้าที่ชัด เช่น `crawl_preview_scope`, `crawl_start`, `crawl_status`, `issue_list` และ `issue_explain` ผู้ใช้จึงสั่งเป็นภาษาคนได้ว่า “ช่วยเตรียม Audit เว็บนี้ จำกัดหนึ่งพัน URL แล้วสรุปปัญหาที่ควรแก้ก่อน”

[ภาพบนจอ: ปิดกั้น Generic Shell, SQL อิสระ, HTTP Fetch อิสระ และ Output Path อิสระ]

สิ่งสำคัญคือ MCP ของ Toad ไม่ได้โยนกุญแจทั้งเครื่องให้ Agent มันไม่มี Shell ทั่วไป ไม่มี SQL อิสระ ไม่มีสิทธิ์เลือกไฟล์ปลายทางตามใจ และไม่สามารถปิด TLS, Robots, Scope Guard หรือ Response Budget ได้

ตัว MCP คุยกับ AI Client ผ่าน standard input/output แล้วเชื่อม Local API ที่ Loopback จึงไม่ต้องเปิด MCP Port ออกสู่อินเทอร์เน็ต

อย่างไรก็ตาม MCP ไม่ได้ลบเรื่องสิทธิ์ออกไป การกด Start ยังส่ง Request ไปยังเว็บไซต์จริง ผู้ใช้ต้องเป็นเจ้าของหรือได้รับอนุญาตก่อนทุกครั้ง

ประโยชน์ที่แท้จริงคือ AI ช่วยแปลงคำสั่งของเราเป็นขั้นตอนเทคนิค ลดงานกดและงานจำ แต่ขอบเขต การอนุมัติ และการตัดสินใจยังอยู่กับคนครับ
